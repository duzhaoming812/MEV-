# 蛟龙16Pro EC寄存器参考

基于同方(Tongfang)模具的通用EC寄存器定义，针对机械革命蛟龙16Pro (MRID6) 适配。

## 结论：本文件中的裸寄存器地址在蛟龙16Pro上全部不可用（2026-10-17 实测）

本文件下面列出的地址是 **RWEverything 风格的裸 EC RAM 偏移**（通过 IO 端口 0x62/0x66、
键盘控制器协议命令 0x80 读 / 0x81 写访问）。这与程序实际使用的
**MICommonInterface WMI command ID** 是两套完全不同的命名空间，数值碰巧相近极易混淆
（例如 WMI command 0x17 = CPU 功耗，裸偏移 0x17 = 无关字节）。

2026-10-17 用 LibreHardwareMonitor 的 Ring0 在本机直接做端口读写，结论是这条路在本机走不通：

| 测试 | 期望 | 实测 |
|------|------|------|
| `0x66 ← 0xEC`（i8042 接口自检） | 0x62 返回 0x00 | **无应答**（OBF 始终为 0） |
| `0x64 ← 0xAA`（键盘自检） | 0x60 返回 0x00 | **无应答** |
| `0x64 ← 0x20`（读命令字节） | 0x60 返回配置字节 | **无应答** |
| `0x66 ← 0x80` + `0x62 ← addr` 读 19 个候选偏移 | 返回 RAM 值 | 第一笔返回 `0x18=0x3D`，之后 **全部超时** |
| 状态端口 0x66 | bit0=OBF bit1=IBF | 0x00 / 0x08，OBF 从不置起 |

即：本机的 0x60–0x6F 不是主机可直读的 i8042/EC 通道。ACPI 访问 EC 走的是芯片组内部的
索引接口（OpRegion），由 ACPI 解释器独占；用户态端口 I/O 打进去的字节没有被 EC 状态机接收。
第一笔读到的 `0x3D` 极可能是 ACPI 尚未取走的 EC 事件通知字节——抢走它正是早期版本
"用裸 EC 后 Fn 快捷键失灵"的原因（见任务 #20）。

因此：
- **不能读，就不能验证；不能验证就不能写。** 对功耗/温度类偏移做盲写，既可能完全无效，
  也可能真的改到热失控门限值而无从回读，属于不可接受的盲操作。裸 EC 写路径已从代码中删除。
- 唯一可用的控制面是 MICommonInterface WMI（见下表"已验证 WMI command"）。
- 由此，**独显 TGP 在本机没有任何软件可达的调节接口**：`nvidia-smi -pl` 不支持
  （`power.limit` 恒为 `[N/A]`），裸 EC 不可用，TGP 由 EC 固件 + NVPCF(Dynamic Boost) 管理。
  80W 默认上限、140W 硬件上限是固件写死的。

## 已验证 WMI command（程序实际使用）

| command | 含义 | 取值 |
|---------|------|------|
| 0x08 | 性能模式 | 0=游戏 1=狂暴 2=办公 |
| 0x09 | 显卡输出模式 | 0=混合 1=独显直连 |
| 0x0D | 风扇 RPM | CPU/GPU 各 16bit |
| 0x0F | A 面 Logo 背光 | 1=亮 0=灭，可写可回读；无颜色通道 |
| 0x10/0x11/0x12 | 键盘灯效模式/颜色/亮度 | — |
| 0x13 | 电源适配器类型 | — |
| 0x14/0x15 | 风扇满速开关/满速档位 | 写入可存储，转速仍受温度硬件门控 |
| 0x16 | CPU 温度 | 只读，写入被物理传感器覆盖 |
| 0x17 | CPU 功耗 | sub 0x02=SPL(持续) 0x03=SPPT(短时)，单位瓦，**只写不回读** |

| GPU风扇低字节 | 0xD3 | RPM低8位 |

## 调试方法

### 使用 RWEverything

1. 下载 RWEverything (http://rweverything.com/)
2. 以管理员身份运行
3. 切换到 "Embedded Controller" 标签
4. 可以实时查看和修改EC寄存器

### 使用 HWiNFO

1. 打开 HWiNFO64
2. 在传感器面板中查看 EC 数据
3. 对比温度/风扇数据确认寄存器地址
