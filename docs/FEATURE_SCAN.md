# 功能与信息扫描清单

本轮扫描目标：找出这台机器上**还能加进控制台的功能**和**还能展示的信息**。
所有探测均为只读；只有明确验证过语义的亮度/音量控制发生了写入。

扫描方法：

- EC：`MICommonInterface` 的 GET(0xFA) 遍历 command 0x00–0xFF（不发送任何 SET）；
- 传感器：LibreHardwareMonitor 0.9.3 全传感器导出；
- 信息：CIM/WMI（电池、显示器、存储、内存、系统）；
- 控制面：WMI 屏幕亮度、CoreAudio 音量各做了一次“写入→回读→恢复”验证。

## 一、EC 命令空间：没有隐藏功能

0x00–0xFF 全部返回 32 字节，但只有以下命令的 payload 非零：

| command | 含义 | 本次读取 |
|---------|------|----------|
| 0x08 | 性能模式 | 1（狂暴） |
| 0x09 | 显卡模式 | 1（独显直连） |
| 0x0D | 风扇 RPM | CPU 2671 / GPU 2698 |
| 0x0F | Logo 背光 | 1 |
| 0x10 / 0x11 / 0x12 | 键盘灯效/颜色/亮度 | 1 / FF0080 / 3 |
| 0x13 | 电源适配器 | 2（原装） |
| 0x14 | 风扇满速开关 | 1 |
| 0x16 | CPU 温度 | 63°C |

其余命令（含 0x15、0x18–0xFF）payload 全为 0；0x17 为只写不回读。
结论：**没有隐藏的风扇曲线、充电阈值、EC 版本等命令**，无法新增这类控制。

| 信息 | 来源 | 展示位置 |

| CPU 全核频率范围 + 总负载 | LHM `Clock`/`Load` | CPU 卡片 |

## 三、已加入控制台的控制

| 控制 | 实现 | 验证 |
|------|------|------|
| 屏幕亮度 0–100% | `WmiMonitorBrightnessMethods.WmiSetBrightness` | 写入 47→回读 47→恢复 48 |
| 系统音量 0–100% | NAudio CoreAudio `AudioEndpointVolume` | 写入 20→回读 20→恢复 14 |
| 静音/取消静音 | 同上 | 可读写；静音锁定时每秒回压，Windows 音量面板/媒体键/其它程序无法解除 |
| 电源方案切换 | `powrprof!PowerEnumerate/PowerSetActiveScheme` | 平衡↔高性能切换并回读 |
| 屏幕刷新率切换 | `EnumDisplaySettings/ChangeDisplaySettings` | 240→60→240，先 CDS_TEST |

原有 EC 控制（性能档、显卡模式、灯效、Logo、功耗墙等）保持不变。

## 四、评估过但未加入

| 候选 | 结论 | 原因 |
|------|------|------|
| 风扇手动转速/曲线 | 不可用 | EC 0x15 写入只存储、转速仍由温度门控；扫描无其它风扇命令 |
| 电池充电阈值（如 80%） | 不可用 | EC 命令空间没有对应命令，厂商 WMI 也未暴露 |
| EC/MCU 固件版本 | 不可用 | 无版本命令；键控 MCU 是独立 USB HID，不提供版本通道 |
| 独显 TGP | 不可用 | `nvidia-smi power.limit` 为 `[N/A]`，固件锁定 |
| 每键 RGB（ITE 048D:8910） | 未实现 | HID 协议未公开，盲写风险高；现有 EC 灯效已覆盖 |
| HDR 切换 | 未实现 | 需要 DisplayConfig/注册表组合，风险高于收益 |
| Wi-Fi/蓝牙开关 | 可加 | Windows Radio API 可用，与性能控制关联弱 |
| NVMe 通电小时/读写错误计数 | 部分不可得 | 本机 WMI 可靠性计数器返回空，LHM 只给容量/损耗/读写量 |

## 五、压测自适应规则

| 目标 | 规则 |
|------|------|
| CPU | 工作线程 = 逻辑处理器数（8 核用 8，32 线程用 32），不超订 |
| 内存 | 目标 = min(物理内存 35%, 当前可用 60%, 可用−2GB)，512MB–16GB；写线程 = 每 8 个逻辑处理器 1 个（1–4 个）；用非托管内存分配，停止/到点即归还系统，不留已提交的大对象段 |
| 磁盘 | 目标 = 临时目录所在盘剩余空间的 10%，256MB–4GB，至少留 2GB；读写共用一块 4MB 缓冲，停止时删除临时文件 |
| GPU | 仅状态探测；没有 nvidia-smi 时禁用，不伪造压测负载 |

CPU 每核表按核心数自适应 2–4 列（每列约 8 行），线程更多的机器不会把卡片无限拉长。

## 五之二、刷新节奏（全部实时，不因页面不可见而停）

| 数据 | 来源与节奏 |
|------|------------|
| CPU/GPU 温度、功耗、频率、电压、每核负载 | LibreHardwareMonitor 采集 2s，界面每 1s 取最新值 |
| EC 档位/风扇转速/AC 类型/键盘灯色 | 后台线程 3s 一轮（桥命令），UI 每 1s 显示最新读值 |
| 亮度、音量/静音、电源方案 | 3–5s 轮询回读，外部改动会同步回界面 |
| 屏幕刷新率 | 10s 轮询 `EnumDisplaySettings` |
| 独显遥测（温度/功耗/频率/显存） | `nvidia-smi` 每 6 轮（约 12s）取一次并缓存；连续失败 3 次后退避到约 80s，避免反复拉进程 |
| 设备详情（型号/健康/容量/序列号） | 静态信息启动时采集一次，动态部分（电池循环、可用空间、适配器状态）随上述轮询刷新 |

界面所有分区每 1s 都会刷新一次，即使当前显示的是别的页面、或窗口收进托盘；
托盘提示每 5s 更新一次。压测期间额外每秒采样温度/功耗/转速用于最小/平均/最大统计。

## 六、安全边界

- 平台/EC 探测只发 GET；不写未知寄存器。
- 新增写入仅限：屏幕亮度（标准 WMI 方法）、系统音量（标准 CoreAudio）、
  以及原本已验证的 EC 命令。
- 充电阈值、风扇占空比、TGP 等没有可靠入口的功能不做猜测式写入。
